# 用 Rust 重写服务

服务原来是 Bun 运行的 TypeScript（Hono + Drizzle），现在用 Rust 重写，按 Rust 的惯用写法设计，TypeScript 的实现与工具链全部删掉。技术栈是 axum + tokio、sqlx（PostgreSQL）、reqwest（rustls）、jiff、tracing。这是重写而不是移植：旧实现只用来弄清对外行为；已有的库原地迁移，数据不丢。

几处取舍：

- **节假日两条接口只保证路径与成功时的响应体**：调用方只有自己的其他程序。`/api/holiday/is-holiday` 与 `/api/holiday/detail` 的路径、成功时的响应体保持不变；其余按 axum 的惯例来：路径对、方法不对的请求由 404 改成 405 并带 `Allow` 头。所有失败的响应体仍统一是 `{statusCode, message, error}`，调用方只写一套错误处理。`date` 参数直接交给 jiff 按 ISO 8601 解析（`20260104`、`2026-01-04T10:30` 也能查），省略表示今天；空串与写错的日期回 400，文案是 axum 的英文原话，不再是旧实现的「日期格式错误，应为 YYYY-MM-DD」，旧实现里空串表示今天的约定也取消了。
- **表结构趁机重整，旧的库原地转换**：`holiday_days` 只剩 `date`（原生 `date` 类型，主键）、`is_off_day`、`name` 三列，去掉了 drizzle 列约定留下、业务上从来不读的 `id`、`created_at`、`updated_at`。第一条迁移识别旧表：有旧表就原地改列、保留往年数据，否则直接建新表；drizzle 的迁移登记（`drizzle` schema）一并删掉。
- **环境变量改名**：`EH_USER_AGENT`、`EH_REQUEST_TIMEOUT` 改成 `OUTBOUND_USER_AGENT`、`OUTBOUND_TIMEOUT`。`EH_` 是早年与图集浏览共用出网时留下的前缀。这两项都有默认值，部署里显式配过的要跟着改名。
- **出网超时交给 reqwest**：旧实现为了绕开 Bun fetch 的限制，自己包了响应流来计算两段超时。reqwest 的 `read_timeout` 在每次读时计时、读到数据就重新计时，等响应头也算在内，正好就是「按多久没收到一个字节算」；连接超时用 `connect_timeout`。
- **显式传状态，不用全局单例**：连接池经 axum 的 `State` 传给处理函数；节假日数据源是一个值，地址作为构造参数，正式环境传 GitHub 的地址，测试传本机的假数据源。测试接缝就在这里，不引 mock 库。
- **SQL 用运行时的 `sqlx::query_as`，不用编译期检查的 `query!` 宏**：一共只有几条 SQL，都有集成测试兜着。用宏的话，构建要连库或者提交一份 `.sqlx/` 离线缓存，再多装一个 sqlx-cli。

## Consequences

- 部署镜像是 distroless 上的一个 musl 静态二进制；迁移与北京时区数据都编进二进制，镜像里不需要 tzdata。
- 第一次在已有的库上启动时会改表结构。这一步只执行一次，由 sqlx 登记在 `_sqlx_migrations`；想回到 TypeScript 版，就得手工把表改回去。
