# 鉴权不用 Passport，全局 Guard 加官方 JWT 模块

本站账号的鉴权只有三件事：用户名和密码换一张无状态令牌、请求头带令牌认人、少数接口放行。Passport 为多种登录策略设计，只用一种 JWT 策略时它多出来的是一层策略注册与 `AuthGuard('jwt')` 的间接调用，读代码时要先弄懂它的约定。所以按 Nest 官方文档的写法：全局 `AuthGuard` 用 `@nestjs/jwt` 验令牌，接口默认要求登录，`@Public()` 以元数据标出放行的接口，`@CurrentUser()` 参数装饰器把当前本站账号 id 注入控制器（公开接口上没登录时是 `null`，不回 401）；令牌是 HS256 的 JWT，签名密钥是从主密钥派生的子密钥，只认 HS256，不照令牌头里自称的算法去验。密码用 `argon2` 包算 argon2id，参数显式写死，与库里已有的哈希一致；账号不存在时也算一遍假哈希，响应快慢不泄露哪些用户名存在。

Kotlin 版时期手写了 JWT 的签发与校验；换到 Nest 之后，官方 JWT 模块已经把这件事做对了，自己再写一遍没有好处，令牌格式不变，旧令牌照样认得。

## Consequences

- 默认要登录、放行靠显式标注：漏标的代价是多一次 401，而不是把接口裸露出去。公开接口的清单由接口测试按整张路由表锁住，新增公开接口必须同时改那份清单。
- 令牌无状态，服务端不存已签发的令牌，没法提前作废，也没有 logout 接口；要全端下线得另加令牌版本号并在每次校验时查库。
- 图片接口由 `<img>` 直接发起、带不了请求头，不走令牌，靠地址签名认人，同样标 `@Public()`，每条接口自己校验签名。
- 登录不再限制同时在算的哈希个数：每算一次要占 64 MiB，大量并发的乱填登录会把内存顶上去。注册默认关闭、账号都是自己人，这个风险先接受。
