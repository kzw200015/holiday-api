# 后端从 Elysia 换成 Hono，前端经 hono/client 推断接口类型

ADR-0007 让前端从后端的 `App` 类型推断接口，但 Eden 推断「请求要传什么」时用的是 schema 的**输出**类型（对 zod 这类 Standard Schema 写死了取 `output`），处理函数拿到的也是输出类型，两头共用同一份。于是 zod 的 `.default()` 与 `.transform()` 在请求 schema 上都用不了：带默认值的字段前端也得给全，要转换的只能挪进处理函数（阅读历史的游标就是这么做的）。这是 Elysia 类型设计上的事：路由方法的签名从同一处推出处理函数的上下文与前端看到的路由表，1.4 与 2.0 beta 都是如此，上游的 issue 没有回应，补丁打不进去。

Hono 的 `hc` 客户端把两头分开：前端推断出的是 schema 的**输入**（带默认值的字段可选，路径参数是 transform 之前的字符串），处理函数经 `c.req.valid()` 拿到的是输出。所以后端换成 Hono，前端的 Eden 换成 `hono/client`。对外行为基本不变：路径、`{statusCode, message, error}` 的失败体、令牌与图片签名全部兼容；只回成败的写接口由 200 空体改成 204，「我是谁」没登录时由空体改成 JSON 的 `null`，这几条接口只有本站前端在调。

几处取舍：

- **入参校验经 `validate.ts` 包一层 `@hono/zod-validator`**：不合格时直接抛 400，由 `app.ts` 的 `onError` 回成统一的失败体。按 `zValidator` 默认的做法回一个响应的话，zod 的错误对象会被推断成每条接口的一种响应，混进前端的类型。
- **鉴权中间件逐条写在路由上，不在一组路由上 `use`**：Hono 的 `use` 按路径前缀挂，eh 下要登录的路由与公开的图片接口共用前缀，挂在一组上会把图片接口一并拦住。`signedIn` 与 `maybeSignedIn` 用 `createMiddleware` 写，`c.get("userId")` 带着类型，排在入参校验之前，没登录的请求照旧先拿到 401。公开接口的清单照旧由接口测试按整张路由表锁住。
- **监听由 `server.ts` 自己 `Bun.serve`**：Hono 的应用只是一个 fetch 函数。`idleTimeout` 照 Elysia 原来的值设成 30 秒：Bun 默认 10 秒，手动同步标签译名这类要十几秒的请求会被掐断。静态文件改用 `hono/bun` 的 `serveStatic`，只挂在 GET 上（它自己不看方法），缓存头在 `onFound` 里按路径设；请求日志照旧自己写，不用 Hono 的 `logger`：日志格式是这里定的。
- **ADR-0007 的其余取舍不变**：不用依赖注入、模块就是单例，定时任务用 croner，前端只 `import type` 后端的 `App`，接口收什么、回什么都定义在后端。

## Consequences

- 请求 schema 可以照常用 `.default()` 与 `.transform()`：前端看到的是输入，处理函数拿到的是输出。阅读历史的游标改回在 schema 上解开。
- 前端的调用写法按路由的原样展开：路径参数写成 `api.eh.galleries[":gid"][":token"].$get({ param: { gid: String(gid), token } })`，请求体放在 `json`、查询串放在 `query`，`signal`、`keepalive` 放在第二个参数的 `init` 里。`httpClient.ts` 的 `request` 用 `hono/client` 的 `parseResponse` 按推断出的类型读响应体，失败时从它抛出的 `DetailedError` 取状态码与响应体。只回成败的写接口回 204：`c.body(null)` 回 200 的话，`parseResponse` 会把它推断成 `string`、读出一个空串，204 才推断得出 `undefined`、读出来也是 `undefined`。
- 路由要从 `new Hono()` 一路链式写下来，`App` 类型里才有全部接口；子路由经 `.route(前缀, 子路由)` 挂上。
- 前端的类型检查照旧读到后端源码，ADR-0007 列的 `erasableSyntaxOnly` 约束不变；前端的 `lib` 升到了 ES2023，后端可以用 `toSorted` 这类方法；前端也照旧看得到 Bun 的全局类型，这回是后端源码自己引了 `bun`。
