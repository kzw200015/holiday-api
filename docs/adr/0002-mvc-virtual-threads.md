# Spring MVC + 虚拟线程，不用 WebFlux

数据访问选了 MyBatis，它跑在阻塞的 JDBC 上；在 WebFlux 里用它，每次查库都得切到 `Dispatchers.IO`，而且这部分既不能取消也不省线程，等于两套并发模型混着用。所以 Web 层用 Spring MVC 并开启虚拟线程，代码按直写的阻塞风格来；Kotlin 协程只用在一个请求内部需要并发的几处（例如详情页同时读阅读进度和元数据），跑在虚拟线程承载的 dispatcher 上，控制器不写成 `suspend`。

## Consequences

- 浏览器中止请求（阅读器里快速翻页时会成批中止图片请求）不会连带取消正在进行的上游请求链，要等往回写失败才停，比 Go 版多打一些 e 站请求。
- 事务和日志 MDC 挂在 ThreadLocal 上，不会自动带进子协程：事务不能跨越并发的那几处，日志上下文要显式传。
