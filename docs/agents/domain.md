# 领域文档

约定各类工程技能在探索本仓库代码时，应如何消费领域文档。

## 探索之前先读这些

- 根目录的 **`CONTEXT.md`**，或
- 根目录的 **`CONTEXT-MAP.md`**（若存在）—— 它指向每个上下文各自的 `CONTEXT.md`，与主题相关的都要读。
- **`docs/adr/`** —— 读与即将动工区域相关的架构决策记录。

这些文件若不存在，**静默继续**：不要提示缺失，也不要建议提前创建。`/domain-modeling` 技能（可经 `/grill-with-docs` 与 `/improve-codebase-architecture` 进入）会在术语或决策真正需要落定时按需创建。

## 文件结构

本仓库为单上下文布局：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
├── backend/
└── frontend/
```

## 使用术语表中的词汇

输出内容涉及领域概念时（工单标题、重构提案、假设、测试名称等），一律采用 `CONTEXT.md` 中定义的术语，不要漂移到术语表明确回避的同义词。

若需要的概念还不在术语表里，这本身就是信号：要么是在生造项目并不使用的说法（需要重新斟酌），要么是确有缺口（记下来交给 `/domain-modeling`）。

## 与 ADR 冲突时明确指出

若输出与既有 ADR 相抵触，必须显式点明，不要默默推翻：

> 与 ADR-0007（事件溯源订单）相抵触 —— 但值得重新讨论，因为……
