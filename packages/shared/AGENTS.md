# @myapi/shared

两端都要执行的规则：前端据此列选项、提交前预校验、按同一条规则当场改本地数据，后端据此校验入参、落库。全仓通用的约定见根目录 `AGENTS.md`。

## 引用

这是只有源码的工作区包，不构建：`exports` 直接指向 `src/*.ts`，前后端都照普通依赖引用，由各自的工具当场编译——后端是 Bun，前端是 Vite 与 vue-tsc（见 ADR-0004）。改了两端直接看见，不用构建也不用 watch；`typecheck` 脚本只做类型检查。没有汇总入口：`src/` 下每个文件就是一个子路径（`exports` 的 `./*`），按领域分文件、与后端模块和前端 feature 同名（`text.ts` 是两端共用的长度口径），引用时写到领域，如 `@myapi/shared/eh`；新增一个领域加一个文件即可，不用改 `package.json`。包内引用用相对路径、不写扩展名：这里的源码是由前后端各自的配置编译的，路径别名只在各自的包里定义，共享包里写了别名，两端都解析不了。

## 放什么

只放两端都真的要执行的东西：分类与最低评分的取值（前端列选项，后端校验、换算上游参数）、自动翻页间隔与搜索历史的词这两条字段规则（前端提交前先挡，后端校验时拼进路由的 schema）、记一个搜索词的规则 `recordSearchKeyword`（前端当场改本地那份，后端落库）、还没存过偏好时的默认值、两端共用的长度口径 `text.ts`。规则的文案是给用户看的中文，校验失败时原样显示。

不放接口的形状：请求体、查询串、路径参数的 schema 都写在后端的路由上，响应类型定义在后端产出它的模块里（见 `apps/server/AGENTS.md`），前端的出入参类型从 `hono/client` 的调用推导（见 `apps/web/AGENTS.md`）。「两个接口收的东西长得一样」不是放进来的理由，那是后端就近共用的事。也不从这里给接口的数据标类型：前端不引这里的类型，后端的领域类型（如 `GalleryCategory`）引这里只因为取值就定义在这里。
