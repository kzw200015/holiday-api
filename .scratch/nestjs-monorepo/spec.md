# 后端改用 NestJS 重写，与前端组成 pnpm monorepo 并共享 zod schema

Status: ready-for-agent

## Problem Statement

前端的领域类型（图集卡片、详情、评论片段、绑定状态、偏好、阅读历史等）靠手工与 Kotlin 后端「逐字对齐」：后端改了字段名或形状，前端编译照样通过，只能在运行时发现。入参校验规则也各写一份——后端校验搜索词不超过 200 字节、搜索历史最多 10 条、自动翻页间隔 1–20 秒，前端为了「整份提交不被退回」又得原样再挡一遍，两处规则随时可能漂移。

维护者希望后端与前端同为 TypeScript，放进同一个 pnpm 工作区，由一个共享包同时承载「请求的校验规则」与「响应的类型」，让任一侧改动在编译期就暴露在另一侧。3 月做过一次类似的 monorepo（Hono + Drizzle），共享包靠 tsconfig paths 加 vite alias 直接解析源码，别扭且脆弱，8 月随换 Go 撤掉；这次要用标准的工作区包形式。

## Solution

后端用 NestJS 12 重写，仓库改为 pnpm monorepo：`apps/web`（现有前端原样迁入）、`apps/server`（新后端）、`packages/shared`（共享的请求 zod schema 与响应类型，编译成标准的 ESM 包经 `exports` 暴露）。后端用 Nest 12 自带的 Standard Schema 校验直接吃共享的 zod schema；前端提交前用同一份 schema 预校验、从同一个包取响应类型。

接口契约允许变，以 Nest 与后端的惯用约定为优先：去掉 `{code,data,msg}` 外壳，成功直接返回数据，失败用 Nest 默认错误体。数据库沿用现有库和数据，表结构交给 drizzle-kit 做版本化迁移；本站账号的旧密码哈希、旧登录令牌、旧图片签名地址全部继续有效，读者无感知。部署仍是单镜像单进程，同一进程提供 `/api` 与前端静态文件，端口 8000。

## User Stories

### 读者（本站账号的持有者）

1. 作为读者，我希望重写上线后不用重新登录，以便无感知地继续使用（旧登录令牌照常有效）。
2. 作为读者，我希望用原来的用户名和密码登录成功，以便账号不因换栈丢失（argon2id 旧哈希验得过）。
3. 作为读者，我希望用户名区分大小写的规则不变，以便 `Alice` 与 `alice` 仍是两个本站账号。
4. 作为读者，我希望用户名不存在与密码错误得到同一句提示，以便别人无法借提示探出哪些用户名存在。
5. 作为读者，我希望登录的响应耗时不因用户名是否存在而不同，以便别人无法借耗时探出用户名。
6. 作为读者，我希望本站关闭注册时看到明确的中文提示，以便知道不是我操作有误。
7. 作为读者，我希望已绑定的 e 站账号在重写后仍然有效，以便不用重新复制 e 站凭据。
8. 作为读者，我希望绑定 e 站凭据时后端先实际验证一次，无效就不存，以便不会存进一组用不了的 Cookie。
9. 作为读者，我希望绑定后能看到「已绑定 xxx」以及是否有里站权限，以便知道能看哪个站。
10. 作为读者，我希望解绑 e 站账号后立即生效，以便后续请求不再带着旧凭据访问 e 站。
11. 作为读者，我希望有里站权限时默认浏览里站、也能降级到表站，未绑定时匿名浏览表站，以便选站规则与现在一致。
12. 作为读者，我希望搜索图集时关键词、分类条件与触底加载的翻页行为不变，以便来源列表的体验不变。
13. 作为读者，我希望输入超过 200 字节的关键词在前端就被挡下并看到中文提示，以便不必等服务端退回。
14. 作为读者，我希望前端的这条限制与服务端完全一致，以便不会出现前端放行、服务端又退回的情况。
15. 作为读者，我希望图集详情页照常显示标题、分类、标签、页数、大小、评分、是否已删除，以便信息不因重写缺失。
16. 作为读者，我希望详情页带上我的阅读进度，以便从上次读到的页码继续。
17. 作为读者，我希望评论照常显示作者、时间、分数与正文，正文里的链接只放行 http/https，以便不引入 XSS。
18. 作为读者，我希望重写前浏览器缓存过的图片地址仍然命中缓存，以便不重复消耗图片配额。
19. 作为读者，我希望阅读器里大图照常逐页加载、失败时自动换源重试一次，以便偶发的节点故障不打断阅读。
20. 作为读者，我希望图片传到一半断掉时浏览器不会把半张图缓存下来，以便重试时能拿到完整的图。
21. 作为读者，我希望图片配额用尽、出口 IP 被临时封禁、里站不放行、图集不存在等情况各有准确的中文提示，以便知道该等一等还是该检查 e 站凭据。

23. 作为读者，我希望篡改图片地址里的身份或过期时间会被拒绝，以便别人拿不到我的图片访问权限。
24. 作为读者，我希望翻页上报阅读进度的节奏与合并窗口不变，以便自动翻页时进度照常保存。

32. 作为读者，我希望自动翻页间隔超出 1–20 秒时前端就被挡下，以便整份提交不会一直失败。
33. 作为读者，我希望搜索历史最多保留 10 条、单条 1–200 字节的规则前后端一致，以便整份提交不会一直失败。

## Implementation Decisions

### 仓库与工具链

- pnpm 工作区，三个包：`apps/web`（现有前端整体迁入，内部结构与约定不变）、`apps/server`（NestJS 后端）、`packages/shared`（共享包）。`packageManager`、锁文件与工作区设置提到根目录；原生模块 `argon2` 加入允许执行构建脚本的名单。
- Node 24 LTS，全仓 ESM。
- 根目录一份 Prettier（无分号、双引号、120 列、import 自动排序）与一份 oxlint 配置，覆盖三个包；Nest 脚手架自带的格式配置不保留。`apps/web` 下 shadcn-vue 生成的源码继续排除。
- 根目录提供聚合脚本：并行 dev（共享包 watch + server + web）、全仓 build / test / lint / format:check。

### 共享包

- 只放两类东西：**请求**的 zod 4 schema（注册与登录、e 站凭据、图集搜索、偏好、搜索历史、进度上报、阅读历史游标等），以及**响应**的 TS 类型（由 `z.infer` 推出或直接写 `interface`，不做运行时校验）。
- 校验失败的中文文案写在 schema 里。长度口径按业务原义实现：密码按 code point 计数，关键词与搜索历史按 UTF-8 字节计数，不用 JS 字符串长度。
- 用 `tsc` 编译到 `dist`，经 `package.json` 的 `exports` 暴露类型与 ESM 产物；不用源码直连、不用路径别名。
- 前端的 `model.ts` 改为从共享包取类型；需要预校验的组合式函数（搜索、搜索历史、偏好）直接复用共享 schema。

### 后端框架

- NestJS 12（官方脚手架 ESM 模板生成，自带 Vitest、oxlint），Express 适配器，Nest 自带 Logger。
- 模块按领域划分：`auth`、`eh`、`holiday`，另有数据库、配置、签名（主密钥派生）等基础模块。控制器只做入参转换，不设门面。`eh` 内部的上游协议层（出网、解析、上游失败翻译）只在 `eh` 模块内使用。
- 入参校验用 Nest 12 自带的 `StandardSchemaValidationPipe` 全局启用，控制器参数上用 `@Body({ schema })` / `@Query({ schema })` 挂共享 schema。数字路径参数用 Nest 内置的整数解析管道，`1.5`、`abc` 这类回 400。
- 前端静态文件用 `@nestjs/serve-static`，沿用 Express 静态中间件的默认缓存头（`max-age=0` 加 ETag，效果与现在的 `no-cache` 等价），不另配置。

### 接口契约（有意变更）

- 去掉 `{code,data,msg}` 外壳：成功直接返回数据本身，只回成败的接口返回空体。
- 失败使用 Nest 默认错误体 `{statusCode, message, error}`，中文文案放在 `message`；schema 校验失败时 `message` 为字符串数组。
- 业务失败直接抛 Nest 自带的 HTTP 异常（400 / 401 / 403 / 404 / 429 / 502），删除自定义异常层级与统一异常翻译器；未预料的异常由 Nest 默认处理为 500，原文进日志。
- 休息日查询接口直接返回布尔值；外部调用方同步修改。
- 接受以下行为变化：路径存在但方法不对时回 404 而非 405；不带令牌又发坏 JSON 时先回 400（请求体先于 Guard 解析）；时间字符串带毫秒（`.000Z`）；登录不再有并发上限与 429 排队。
- 路径、方法、字段名、业务规则与中文文案其余不变（如 `isOffDay`、`isUploader`、`hasExAccess`，详情把卡片字段平铺，评论正文拆成 text / break / link 片段）。
- 前端 `httpClient` 不再解包外壳，报错时读 `message`（兼容字符串与字符串数组）。

### 鉴权（改写 ADR-0001）

- 按 Nest 官方文档的做法：全局 Guard + `@nestjs/jwt`，`@Public()` 以元数据标记放行，`@CurrentUser()` 参数装饰器注入当前本站账号 id，参数可空即允许未登录；不用 Passport。与 ADR-0001「不用安全框架、手写鉴权」的精神一致，但实现从手写 JWT 改为官方 JWT 模块，ADR-0001 需改写。
- 令牌兼容：JWT 为 HS256，签名密钥是由主密钥派生的令牌子密钥，载荷含 `sub`（本站账号 id 的字符串）与 `exp`；旧令牌必须验得过。
- 密码哈希用 `argon2` 包，参数显式对齐旧值（argon2id、m=65536、t=2、p=1、16 字节盐、32 字节哈希），旧 PHC 串必须验得过。
- 保留「用户不存在时也算一遍假哈希」的计时对齐；去掉登录并发上限与排队 429。
- 注册默认关闭，由配置开启。

### 签名（主密钥派生）

- 子密钥派生算法照旧：对「主密钥原文 + 冒号 + 用途标签」做 SHA-256，用途标签为令牌与附件两种，与现有版本逐字一致。业务模块只拿派生后的子密钥。
- 图片地址签名照旧：HMAC-SHA256 取前 16 字节转小写 hex，过期时间向上对齐到有效期四分之一的窗口，查询串形状、签名覆盖的内容（大图覆盖本站账号 id、gid、token，不覆盖页码；缩略图覆盖原始上游地址）与现在完全一致，旧地址继续有效且命中浏览器缓存。

### e 站交互

- 出网用 Node 自带 `fetch` 配 undici `Agent`：`headersTimeout` 限等响应头，`bodyTimeout` 即空闲超时，所有请求 `redirect: "manual"`。统一 User-Agent，Cookie 手工拼接，取图不带 Cookie。
- 出网函数做成可注入的 provider，这是测试替换 e 站与节假日源的唯一接缝。
- SSRF 白名单语义照旧：仅 https、无 userinfo、主机严格等于 `ehgt.org` 或以 `.hath.network` 结尾；因 WHATWG URL 与 Java URI 的解析差异，白名单用例需全部移植并以旧行为为准。
- 搜索参数按表单编码（空格编为 `+`），与现在一致。
- 图片接口用 `StreamableFile` 流式转发，响应头保持现状（透传 Content-Type、30 天私有 immutable 缓存、`nosniff`、`sandbox` CSP、上游给了才带 Content-Length）；自定义出错处理：响应头未发出时清掉缓存头并回 502，已发出则直接销毁连接。上游 Content-Type 必须是 `image/*` 且不是 SVG。
- 解析：列表、分片、图片页、说明页等照搬现有正则；评论改用 `cheerio`，需对齐 jsoup `.text()` 折叠空白与去首尾空白的行为；HTML 实体解码只认带分号的合法命名实体。
- 上游失败的识别顺序与中文文案照旧（图片配额、临时封禁、里站不放行、内容警告、e 站凭据被拒、图集不存在、e 站提示原文、网络不通）。
- 时间输出沿用 ISO 8601（接受毫秒位变化）；阅读历史游标里的时间按字符串原样传给数据库，不经 JS `Date`，避免微秒截断导致分页漏行。

### 缓存与并发

- 进程内缓存用 `lru-cache`，以其 `fetch()` 实现「同一 key 并发加载只跑一次、失败不缓存」。缓存清单、容量与过期时间沿用现有：e 站凭据、图集元数据（批量补齐时缺的 key 共用一个在途批量请求）、页令牌、分片大小、showkey、图片地址、分片。
- e 站凭据缓存在绑定、解绑时作废，作废需等在途回填完成后生效。
- 一个请求内需要同时等两件互不依赖的事时（详情页并发读阅读进度与元数据、凭据校验并发探测表站与里站、并发刷新当年与次年节假日安排）用 `Promise.all`。

### 数据访问与迁移

- Drizzle ORM + `pg` 驱动。id 与 gid 用 number 模式的 bigint。
- 用 `drizzle-kit pull` 从现有库反推 TS schema 并生成基线迁移，线上库手工登记为已执行；随后一条迁移给时间列补上默认值（`defaultNow()`，更新时间由 `$onUpdate` 维护）。表、列、索引、约束（含搜索历史最多 10 条、自动翻页间隔 1–20 的 CHECK）保持不变。
- 服务启动时用 `drizzle-orm` 的迁移器自动执行未执行的迁移，迁移文件随镜像打包；应用的数据库账号需具备 DDL 权限。
- 需要保留的 Postgres 语义：阅读进度 upsert 带条件的 DO UPDATE（同一上报方只接受更大的序号，不同上报方按到达顺序覆盖）；阅读历史按 `(updated_at, gid)` 行值比较做游标分页；偏好与搜索历史各自 upsert、互不覆盖；节假日安排按年份前缀在同一事务内先删后插，远程为空时不动库；用户名唯一冲突翻译为「用户名已被占用」。
- 节假日日期列仍为 `YYYY-MM-DD` 文本。

### 节假日

- 启动时（`onModuleInit`，早于监听端口）刷新当年与次年，年份按 Asia/Shanghai；失败时库里已有当年数据则记错误继续，否则拒绝启动。
- 之后用 `@nestjs/schedule` 的 `@Cron` 每天固定时刻刷新一次，失败只记日志；去掉刷新间隔配置项。
- 日期入参按严格 ISO 日历日期校验（拒绝 `2026-02-30`、`2026-1-4`），缺省或空串取北京时间今天。

## Testing Decisions

### 什么是好测试

只断言外部可观察的行为——HTTP 状态码、响应体、响应头、连接是否被断开、数据库里最终的状态、发往上游的请求——不断言内部函数调用、缓存结构或模块划分。换一种实现方式（例如换解析库、换缓存库）不应需要改测试。外部依赖一律换成确定性的替身，不引 mock 库。

### 接缝

- **主接缝：服务端 HTTP 边界。** 用 supertest 对完整的 Nest 应用发请求；数据库是 Testcontainers 起的真 PostgreSQL，应用启动时照常跑 drizzle 迁移；唯一的替换点是可注入的出网 provider，测试里换成按请求回放内存响应并记录所有请求的实现（与现有 FakeUpstream 同一思路）。时间相关行为（令牌过期、签名过期与窗口对齐、北京时间的今天）用 Vitest 假时钟控制。原先按单元测的内容尽量上移到这一层：解析器喂真实 HTML 样本后断言接口返回的 JSON；签名闭环、并发加载合并（通过记录的上游请求次数验证）、选站规则、换源重试、进度序号、校验先于出网与落库等都经接口验证。
- **次接缝：真实出网 provider 对着本机 HTTP 服务。** 只测主接缝替换掉就测不到的网络语义：不跟随重定向、空闲超时（慢速但持续的传输不超时、停顿超时）、SSRF 白名单、半截响应时的连接销毁。
- **前端：沿用现有接缝。** `httpClient` 与组合式函数的现有测试调整断言以适配去外壳的响应与新的报错读取；共享 schema 的前端预校验在现有搜索历史、偏好、搜索相关测试里验证，不为共享包单开接缝。

### 要覆盖的行为（按现有测试逐条移植，去掉已放弃的 405 与登录 429）

- 公开接口清单锁定；未登录访问非公开接口回 401；未匹配路径回 404 且不先回 401；坏 JSON 回 400；非法数字路径参数（`1.5`、`abc`、超范围）回 400。
- 注册与登录：用户名唯一且区分大小写、关闭注册时的提示、错误提示不区分原因、旧 argon2id 哈希验得过、每次盐不同。
- 令牌：签发后认得回、Kotlin 版签发的旧令牌认得回、伪造载荷、`alg: none`、换密钥、坏格式、过期均不认。
- 图片签名：旧地址验得过、改 uid 或过期时间回 403、同一窗口签出的地址相同、缺签名参数回 400。
- 图片流：响应头与缓存头、头未发出时的 502、头已发出时的断连、非图片与 SVG 拒收。
- e 站：各种「看起来正常」的上游失败识别与文案、509 提示图、SSRF 用例、e 站凭据探测、showpage 与 gdata 的身份、分片大小推算、页码越界 404、凭据隔离、showkey 回退、换源用本页的 nl。
- 数据：e 站凭据整条替换、偏好与搜索历史互不覆盖、阅读历史游标分页（含同一时刻多行）、进度序号条件 upsert、删除与清空阅读历史、节假日按年替换与远程为空不动库。
- 节假日：启动刷新失败时有当年数据则启动、无则拒绝；严格日期校验；北京时间的今天；表内安排优先、否则按周末判断。
- 响应形状：详情平铺、时间格式、评论片段、休息日查询返回布尔值。

### 先例

- 现有 Kotlin 版的接口契约测试（整套应用 + Testcontainers + 假 e 站 + 假节假日源）是主接缝的直接先例。
- 现有 Mapper 测试（在真 PostgreSQL 上跑表结构后逐个验证查询）的场景并入主接缝。
- 现有取图请求工厂测试（本机真 HTTP 服务验证重定向与空闲超时）是次接缝的先例。
- 现有 e 站 HTML 样本原样搬入新后端测试目录，禁止格式化。
- 前端现有的 `httpClient`、`useSearchHistory`、`useGalleryPreferences`、`useGallerySearch` 等测试。

### 一次性核对（不留成测试）

- 用线上主密钥在本地核对：一条现网令牌与一条现网图片地址在新后端验得过。
