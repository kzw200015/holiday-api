# eh feature（前端）

图集浏览：搜索、详情与评论、阅读器、阅读历史，以及设置页里的 e 站凭据绑定。前端通用约定（分层、读取、换本站账号时的作废、要回执的写入）见 `apps/web/AGENTS.md`。

各份数据的缓存 key 与写入通道在 `queries.ts`：本站账号数据（浏览偏好、搜索历史、阅读进度）的写入走 `useEhWrites`，读它们之前先等写入落地。

## 本站账号数据

偏好按字段 `PATCH`、搜索历史一次记或删一个词（见 ADR-0006），本地当场按同一条规则改好（搜索历史用 `@myapi/shared` 里的 `recordSearchKeyword`，服务端落库用的也是它），改动依次发出，存不上就重读、以服务端为准。会被服务端退回的内容（如超过 200 字节的搜索词）前端先挡掉，挡的规则直接用 `@myapi/shared` 里服务端校验用的同一份 schema。分类是集合，用之前按 `GALLERY_CATEGORIES` 的顺序去重（`normalizeCategories`），搜索结果的缓存 key 才对得上。

偏好由 `EhLayout` 读到后才创建页面组件，因为搜索页的第一次查询要用分类偏好；读不到就停在布局层让用户重试，不拿默认值放行。搜索历史不挡页面。阅读器不在这个布局里，偏好没读到时手上没有当前间隔，自动翻页间隔调不了。绑定状态换绑成功后直接用接口返回的新状态。

## 图集详情与阅读进度

图集元数据（`useGallery`）与读到第几页（`useGalleryProgress`）是两份数据：前者是上游的元数据，后者是本站高频写、写完就要读到的数据，详情接口不带进度（见 ADR-0006）。详情页和阅读器共用一份元数据，每次进入都重读（详情页被 KeepAlive 留着，回来时靠 `useRefreshOnActivated`），重读期间手上那份照常显示，重读失败时照常用、只给个提示，图片地址签的有效期默认有一天。读进度之前先等已经发出的进度保存落地，否则刚退出阅读时读回的还是上报之前的页码。翻页时把页码当场写进进度缓存（先取消在途的读取，免得它带回翻页之前的页码），详情页的「继续阅读第 N 页」不必等网络。

进度上报不排队、当场发出，每次带上这次页面加载的上报方标识和递增序号，服务端只认同一上报方更新的那次，乱序到达也不会让进度回退；排队的话，页面卸载时补发的那次要等前一次回来，那时页面已经没了，`keepalive` 也救不了还没发出的请求。外加合并窗口，免得一本两百页发两百个请求：窗口从一轮第一次翻页起算、到点就发，不随后面的翻页往后推，否则一秒一页的自动翻页一次都发不出去。阅读器一个实例只读一本（`app/App.vue` 用 `readerInstanceKey` 按图集重建），所以窗口里只留一个待发页码，离开阅读页、手改地址换图集、页面收到后台和卸载时都要 `flush()`，换过本站账号就不再发，见 `useReadingProgress`。

阅读历史每次读取前先等已经发出的进度保存落地，否则刚退出阅读时读回的还是上报之前的页码。删除或清空阅读历史时，取消在途的进度读取并把相关进度一并抹成 `null`，否则重进详情会显示一个服务端已经没有的页码。

阅读器横向排列各页，位置计算都经 `readerLayout.ts`：页码从 1 起，用 `offsetOf(page)`、`widthOf(page)` 取，不在调用处自己换算下标。

## 换绑 e 站账号时的作废

换绑成功后调 `invalidateEhContent`：搜索结果与阅读历史只留第一页重读（被 KeepAlive 留着的搜索页不会把翻过的每一页都向上游重抓一遍），详情与评论作废重读；本站账号数据不受牵连。换本站账号时的作废是全前端通用的，见 `apps/web/AGENTS.md`。
