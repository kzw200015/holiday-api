# eh 模块（后端）

图集浏览：e 站凭据的绑定、浏览偏好与搜索历史、搜索、详情、评论与预览图、图片代理、阅读进度与阅读历史。后端通用约定见 `apps/server/AGENTS.md`。

## 结构

- `upstream/` 是与 e 站打交道的协议层，只在本模块内使用：身份与站点（`access.ts`）、图集定位与从链接认出图集、页（`gallery-ref.ts`）、请求与「200 但不是内容」的失败识别（`eh-client.ts`）、失败与文案（`failures.ts`）、HTML 解析（`parse.ts`，先按元素结构定位再取属性与文字，不拿正则扫整页）、分类换算（`categories.ts`）、图片主机白名单（`image-hosts.ts`）。
- 其余是本站这一侧：路由（`*-routes.ts`）与服务按功能成对（凭据、偏好、图集、图片、阅读；`eh-routes.ts` 把各组路由汇总到 `/eh` 下；偏好与搜索历史的写入与到达顺序无关，见 ADR-0006），`gallery-catalog.ts` 是图集元数据的缓存与批量读取，`image-service.ts` 是取图的入口：校验签名、定位、打开图片流、等到第一段数据、图床节点失败时换源，交回路由直接转发的流（路由只定响应头）；`image-locator.ts` 是它内部从图集定位到某页图片地址的链路，详情页分片的缓存也在那里，评论与预览图经它取分片，`attachment-urls.ts` 签发与校验图片地址，`params.ts` 是本模块私有的路径与查询串 schema。标签译名（`tag-translation-*`）的数据源是 GitHub 上的 EhTagTranslation 而不是 e 站，所以不放在 `upstream/` 下。

## 上游失败与文案

e 站那些可预期的失败与文案集中在 `upstream/failures.ts`：配额用尽、出口 IP 被临时封禁这类「过会儿再试」的回 429，要用户自己处理的（Cookie 不对）回 400，e 站没连上或回了意料之外的东西回 502。`message` 只放固定的中文文案，「过会儿再试」只用在 429 上；上游原话、状态码、地址这些细节作为 detail 交给工厂函数，由它在创建 `HttpError` 时记进日志，不拼进文案，也不在抛出的地方另记一遍。与某个上游地址有关的失败（连不上、图床节点取不到、图片传到一半断了）都带上地址。

## 图片

图片地址只接受 `ehgt.org` 与 `*.hath.network` 的 https 地址（`upstream/image-hosts.ts`），这是图片代理唯一的 SSRF 防线，不要放宽；取图不带 Cookie。大图的图床节点失败时带着这一页自己的换源令牌重试一次，缩略图不换源；回了响应头却一个字节都没传就断了、或者回的是空的，也算节点失败。大图地址逐页签发（`pages/:page/image-url`），签名里带着页码，拿一页的签名取不了别的页；签发只算签名、不访问 e 站。详情接口只回图集本身，不带图片地址。

预览图就是详情页各分片上 `#gdt` 里那些按页排的小图，与评论、取图共用同一份分片缓存，按分片序号取（`previews/:slice`）。e 站给的要么一页一张，要么（账号设成普通尺寸时）一片拼成一张、靠背景偏移露出各页，解析成统一的「从这张图的哪里裁出多大」交给前端。里站页面上的预览图在 `s.exhentai.org` 上，不带 Cookie 取不到，按同一路径改到 `ehgt.org` 取（`onPublicThumbnailHost`），而不是放宽白名单或带上 Cookie。评论只有 e 站默认列出的那些，得分低于阈值的只解析出条数，不另抓 `?hc=1`。

## 读取与缓存

图集元数据统一从表站匿名获取，一次要的一批里缓存没有的按上游单次上限切批请求（`gallery-catalog.ts`），每批各自成败。本站账号的 e 站凭据每次从库里读，不缓存：换绑、解绑当场生效。取图途中拿到的页令牌、showkey、分片大小按上游身份（凭据的摘要）与图集隔离，换绑凭据就进入新的作用域。

标签在协议边界拆成命名空间与值（临时标签没有前缀，归到 temp），元数据缓存里存的是这份原文。译名只在设置页手动同步，整表替换（见 ADR-0005）；组装卡片时才按条查译名，一次响应里缓存没有的攒成一条 SQL，没有译名的也进缓存。同步后整个换一份缓存，途中的查询写进它开始时的那份旧缓存，不会把旧译名带进新缓存。
